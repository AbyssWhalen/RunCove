# RunCove v0.2.1 Windows Usability And Diagnostics Plan

## Summary

- Build from the clean `main` baseline at `bf3d532`.
- Keep the Windows-first desktop application and its existing Overview, Ports,
  and Projects navigation. macOS desktop support remains a `v0.3.0` concern.
- Keep automatic discovery review-only: scan a saved development root, present
  candidates, and never register or launch a project without confirmation.
- Do not change CI, release workflows, repository settings, tags, or published
  releases. Do not commit, push, publish, or remove the compatibility CLI.

## Implementation

### Run History

- Add a five-entry Recent Runs section to Overview and a right-side history
  drawer for the existing 200-entry run-history query.
- Support search by project/profile and filters for all, active, exited, and
  interrupted sessions. Show project/profile, PID, start/end times, duration,
  exit code, and persisted status without inferring success from missing data.
- Preserve orphaned history after project deletion. Allow existing profiles to
  be located in Projects, but do not offer historical logs because logs are
  bounded in-memory and are not correlated to run-session IDs.
- Load history when Overview is first opened and after explicit refreshes,
  lifecycle actions, restores, and exit events. Do not query it on every
  two-second port snapshot.

### Actionable Conflicts And Errors

- Add an internal structured port-conflict error while preserving its existing
  string representation. Add optional `relatedPort: { port, protocol }` data
  to run-status and restore results.
- Let a conflict message refresh the snapshot and focus the exact port in
  Ports. If the listener has already disappeared, report that the state changed
  and do not expose stale process actions.
- Include project/profile context in lifecycle and discovery failures. Keep all
  existing confirmations and process identity rechecks; never auto-terminate a
  conflicting process.

### Discovery And Project Editing

- Expose idle, scanning, candidates-found, empty, and failed discovery states,
  including retry. Coalesce concurrent scans, retain candidates when review is
  closed, remove only imported candidates, and replace candidates on rescan.
- Add duplicate-profile editing. Copy structured arguments, cwd, and expected
  ports while clearing persisted IDs and runtime-observation metadata.
- Add field-level validation for project/profile names, directories, program,
  blank arguments, port range, and duplicate ports. Mirror authoritative
  validation in Rust while continuing to allow programs resolved through PATH.

### Port Details, Help, And Visual Quality

- Add clipboard actions for PID, executable path, and command line with
  accessible labels and explicit clipboard errors.
- Add a Run History help topic and explain conflict recovery, restore failures,
  and the non-persistent log boundary.
- Keep all new UI bilingual, keyboard accessible, compact, and consistent with
  the current design system.

## Interfaces And Data

- Do not migrate SQLite or persist polling snapshots/logs. Continue using the
  existing `run_sessions` table.
- Treat frontend history status as `starting | running | exited | interrupted |
  unknown`, mapping unrecognized persisted values to `unknown`.
- Add optional `relatedPort` fields compatibly; existing callers and serialized
  fields remain valid.

## Verification

- Rust: history order/limit/interruption/orphaning, structured conflicts,
  restore conflicts, and project-validation cases.
- Vitest: history loading/empty/error/filter/duration/orphan navigation,
  conflict focusing and races, discovery retention/retry, duplication and
  field validation, clipboard behavior, and bilingual messages.
- Playwright: English and Chinese workflows at `900x600`, `1280x720`, and
  `1440x900`, with overflow, overlap, and console-error checks.
- Run both Rust format/Clippy/test matrices, frontend lint/typecheck/tests/build,
  Edge E2E, and a local Windows Tauri release build.
- Update README, CHANGELOG, HANDOFF, and notes with only freshly observed
  results. Tests use local fixtures and temporary listeners without taking over
  or stopping unrelated development processes.

## Out Of Scope

- macOS desktop support, login startup, automatic launches, Docker, remote
  hosts, persistent logs, `.env` editing, installers, signing, CI/release
  changes, repository changes, commits, pushes, or publishing.
